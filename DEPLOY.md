# Развёртывание «Помощника Пятнашки»

[О проекте](README.md) · [Контакт: @menmamoh](https://t.me/menmamoh)

Бот использует long polling Telegram: отдельный HTTP-домен для него не нужен. Для одного токена запускай один экземпляр polling. Рабочие данные хранятся в SQLite и файлах рядом с базой.

## Переменные окружения

| Переменная | Назначение и значение по умолчанию |
| --- | --- |
| `BOT_TOKEN` | Токен собственного Telegram-бота; обязателен. Получается у @BotFather |
| `ADMIN_ID` | Числовой Telegram ID администратора. Нужен для первой настройки; при отсутствии код ищет ранее сохранённый ID в SQLite |
| `DB_PATH` | Путь SQLite. Без переменной — `debts.db` рядом с `database.py`; Dockerfile задаёт `/app/data/debts.db` |
| `GDRIVE_FOLDER_ID` | ID папки Google Диска. Без переменной используется папка, заданная в `gdrive_sync.py` |
| `BOT_TIMEZONE` | Часовой пояс логики расписания, по умолчанию `Europe/Minsk` |
| `SCHEDULE_CUTOFF_HOUR` | Час переключения целевой учебной даты в обычные дни, по умолчанию `17` |
| `SCHEDULE_SATURDAY_CUTOFF_HOUR` | Час переключения в субботу, по умолчанию `14` |
| `BOT_LOG_FILE` | Необязательный путь файлового журнала. Без него основной журнал доступен в стандартном выводе |

Секреты задавай через переменные хостинга или локальный `.env`. В примерах используй заглушки, а не реальные токены. Для `BOT_TIMEZONE` требуется допустимое имя часового пояса, для часов — целые числа. В Dockerfile системный часовой пояс отдельно задан как `Europe/Minsk`.

Синхронизация читает папку Google Диска по доступным веб-страницам и ссылкам скачивания; доступ к закрытой папке через Google OAuth в этом коде не настраивается. Названия и даты файлов разбирает `gdrive_sync.py`: для собственной папки сначала проверь, что её листы распознаются как замены или консультации.

## Bothost

1. Подключи репозиторий `https://github.com/Menmamohh/study_debt_bot.git`, ветку `main`.
2. Включи использование собственного `Dockerfile`. Он содержит Python 3.11, установку зависимостей и команду `python bot.py`.
3. В переменных бота укажи собственный `BOT_TOKEN` и числовой `ADMIN_ID`. Проверь `DB_PATH=/app/data/debts.db`.
4. Проверь, что папка `/app/data` сохраняется хостингом между пересозданиями контейнера. Наличие каталога в Dockerfile само по себе постоянного хранения не обеспечивает.
5. Запусти сборку, затем проверь статус бота и журнал работы. Если после сборки бот остановлен, запусти его из панели.
6. При успешном старте в журнале видны путь SQLite, количество подтверждённых пользователей и строки `Start polling` / `Run polling`. Проверь `/start` в личном чате.

При первом запуске таблицы, включая историю расписаний, создаются обычной инициализацией базы. Не подменяй рабочую базу пустой копией из локальной папки.

## Хранение данных

Каталог скачанных листов вычисляется относительно `DB_PATH`, а не относительно каталога кода:

| Запуск | База | Листы и копии истории |
| --- | --- | --- |
| Bothost / Dockerfile | `/app/data/debts.db` | `/app/data/schedule/downloads/`, включая `versions/` |
| Docker Compose из проекта | `./data/debts.db` на хосте | `./data/schedule/downloads/`, включая `versions/` |
| Локально без `DB_PATH` | `debts.db` рядом с кодом | `schedule/downloads/`, включая `versions/` |

В SQLite хранятся статусы верификации, группы, предметы и работы, сведения о материалах, настройках и версиях расписаний, анонсы и отметки их чтения или закрытия. Для листов Google Диска история сохраняет отдельные копии изображений в `versions/`; ссылки на эти файлы находятся в базе. Ручные фотографии могут храниться в публикациях как Telegram file ID.

Для восстановления истории нужны **база и весь каталог скачанных листов**, а не только `debts.db`. Сохраняй структуру каталогов и абсолютные пути, записанные в публикациях. Смена пути хранения требует отдельной проверки ссылок в истории.

## Обновление на Bothost

1. До обновления сделай резервную копию рабочих данных.
2. Опубликуй проверенные изменения кода в подключённой ветке GitHub.
3. В панели Bothost выбери «Обновить из Git». Дождись завершения сборки и запуска контейнера.
4. Проверь свежий журнал: правильный путь базы, сохранённые пользователи, запуск polling, отсутствие ошибок старта.
5. Проверь `/start`, расписание и переход к предыдущей публикации.

Обновление одного README не требует ручной пересборки бота. Если настроен webhook автоматического развёртывания, публикация коммита может запускать обновление через хостинг независимо от содержимого коммита.

## Резервная копия и восстановление

На Bothost останови бота на время копирования, чтобы база и изображения соответствовали одному состоянию. Через файловый менеджер или бэкапы хостинга сохрани весь `/app/data`, включая `schedule/downloads/versions/`. Затем запусти бота. Храни архив вне контейнера и не загружай его в публичный репозиторий: он содержит пользовательские данные.

Для Docker Compose из корня проекта можно сделать согласованную копию остановленного приложения:

```bash
docker compose stop bot
mkdir -p backups
tar -czf "backups/data-$(date +%Y%m%d-%H%M%S).tar.gz" data
docker compose start bot
```

При восстановлении останови бота, сохрани текущие данные отдельно и восстанови полную папку данных из выбранной копии по прежнему пути. Проверь права доступа и значение `DB_PATH`, затем запускай. Не копируй поверх активной SQLite только основной файл без учёта WAL: остановка приложения на время полной копии упрощает согласованное восстановление.

## Docker Compose на своём сервере

После установки Docker с Compose и клонирования репозитория:

```bash
cp .env.example .env
# Заполни собственные BOT_TOKEN и ADMIN_ID в .env.
mkdir -p data
docker compose up -d --build
docker compose logs -f bot
```

Файл `docker-compose.yml` подключает `./data` к `/app/data` и задаёт политику `restart: unless-stopped`. Если переносишь существующую установку, сначала выполни резервное копирование и перенеси её данные в выбранный постоянный каталог; одна лишь новая пустая папка `data` прежние данные не восстановит.

## Диагностика

- **Снова требуется верификация:** проверь путь SQLite и подключение постоянного каталога, прежде чем создавать новую базу.
- **История есть, фото не открывается:** проверь наличие файлов `versions/` по путям, сохранённым в публикациях.
- **Нет новых листов:** проверь доступность папки, формат имён файлов и журнал синхронизации. Фоновая проверка выполняется примерно каждые 30 минут; в админке есть ручной запуск.
- **Конфликт polling:** останови второй экземпляр, использующий тот же токен.
