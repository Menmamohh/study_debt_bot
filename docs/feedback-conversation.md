# Переписка в отчётах об ошибках

Администратор отвечает на открытый отчёт через существующий предпросмотр и подтверждение отправки. В новом сообщении с ответом студенту появляется кнопка «Ответить». Старые сообщения администратора не изменяются задним числом.

## Ответ студента

1. Нажать «Ответить» под ответом администратора.
2. Отправить одно сообщение: текст до 3500 символов либо фотографию с подписью или без неё. Следующий ответ можно добавить повторным нажатием «Ответить».
3. Бот сохраняет сообщение в исходном отчёте и показывает подтверждение. Новый отчёт при этом не создаётся.

«Отмена» и переход в главное меню отменяют ввод. После закрытия отчёта старые кнопки больше не принимают ответы; чтобы сообщить о новой проблеме, нужно создать новый отчёт.

Владелец обращения может продолжать переписку и до завершения верификации: это нужно для решения проблем со входом. Доступ к чужому обращению запрещён независимо от статуса пользователя. В групповых чатах переписка недоступна.

## Интерфейс администратора

О новом сообщении студента приходит уведомление с кнопкой открытия исходного отчёта. Карточка показывает переписку с авторами, временем по Минску и пагинацией. Фотографии открываются отдельными кнопками. Администратор продолжает отвечать через существующую кнопку ответа; отчёт остаётся открытым до явного закрытия.

Текст ответа студента и Telegram file ID фотографии хранятся в `feedback_student_messages` рабочей SQLite-базы. Старые ответы администратора остаются в `feedback_replies`; история объединяет обе таблицы. Сообщение сохраняется до попытки уведомить администратора: если уведомление не доставлено, переписка всё равно доступна в очереди отчётов.

Повтор обработки одного Telegram-сообщения не создаёт вторую запись или второе уведомление. Автоматическая повторная отправка ответов администратора при неопределённом результате доставки, как и прежде, не выполняется.

## Проверки

```bash
python -m unittest tests.test_feedback_replies tests.test_feedback_conversation -v
```

Проверки используют временную базу и подмену Telegram API: новые отчёты и сообщения реальным пользователям не отправляются. Проверяются текст, фото, права, закрытие, отмена, повторные обновления, сбой уведомления, сохранение после повторной инициализации базы и общая история двух участников.
