# Даты и отдельные листы расписания

## Как подготовить расписания на пятницу и субботу

Админка → Расписание → Подготовить расписания. Отправьте альбом или выберите исходники с Диска. Для каждого листа подтвердите предложенную дату либо введите ДД.ММ.ГГГГ / ГГГГ-ММ-ДД. Дата получения показана отдельно, в UTC. Предложенная дата берётся из имени, подписи или контекста распознавания и сама публикацию не определяет.

Укажите группы для каждого листа. «Все группы» необходимо выбрать явно. Кнопками предыдущего/следующего листа проверьте весь набор. Через «Добавить листы» можно продолжить загрузку. Общий предпросмотр группирует изменения по датам и показывает получателей. «Опубликовать все даты» сохраняет все подготовленные дни одной транзакцией, с отдельными публикациями по датам.

Публикация разрешена даже если у выбранной группы пока нет подтверждённых студентов: лист сохранится, получателей будет 0.

## Как заменить один лист

Админка → Расписание → Даты и листы расписаний → дата → лист с постоянным номером и названием. Отправьте одну фотографию или текст, либо выберите один исходник с Диска. Дата замены закреплена за исходным листом. Выберите только затронутые группы. При сомнениях бот требует ручной выбор; распознавание не определяет получателей автоматически.

Альтернативный путь: загрузить лист, подтвердить дату и группы, нажать «Вместо существующего листа…». Сравнение показывает старые варианты и новый лист. Перед окончательным подтверждением сравнение повторяется в общем предпросмотре.

Замена для одной группы оставляет прежний лист у остальных. Другие листы и их порядок сохраняются. Замена для всех групп явно меняет этот лист для всех. Предыдущие версии сохраняются; в просмотре есть «Предыдущая версия этого дня».

## Просмотр и уведомления

Студент видит дату и переключатели доступных дней. Кнопка уведомления содержит дату: после публикации субботы ссылка на пятницу продолжает открывать пятницу. Исправление открывается как актуальная версия того же дня. История листов доступна в сохранённых версиях дня; старые публикации без достоверной даты доступны через «Архив прежних публикаций».

Рассылка отправляет только уведомление со ссылкой на день, не пересылает остальные фотографии. Получатели определяются подтверждённой областью изменения; на один день и пользователя создаётся одна запись уведомления. Успешно доставленные уведомления повторно не отправляются при обычном повторе обработки; неудачные остаются в очереди. Как и для любой отправки Telegram, сбой между успешной отправкой и записью результата не позволяет гарантировать строго однократную внешнюю доставку.

## Диск и Gemini

Синхронизация только скачивает исходники. Она не публикует их, не рассылает студентам и не запускает Gemini. Новый или изменённый файл нужно выбрать в редакторе, подтвердить дату, область изменения и публикацию. Ручная замена имеет приоритет до такого подтверждения. Принудительная и повторная синхронизации соблюдают то же правило.

Gemini запускается вручную прежней кнопкой. Проверенный администратором текст проходит через редактор дат и общий предпросмотр. Текст распознавания сохраняется отдельным листом для конкретной группы: бот не угадывает, какой исходный фотолист следует заменить по сводному тексту. При повторной публикации проверенного текста той же группы/даты редактор выбирает прежний текстовый лист. Оригинальные фотографии меняются отдельно, явным выбором.

Новый черновик и ошибка распознавания не скрывают прежнюю подтверждённую публикацию. Отмена не изменяет опубликованные листы. Временные экраны и фото регистрируются и убираются после успешного перехода.

## Хранение, миграция и обновление

Новые таблицы: `dated_migrations`, `dated_batches`, `dated_publications`, `dated_sheets`, `dated_revisions`. Существующие таблицы, пользователи, материалы, старые расписания и файлы не удаляются. Версии опубликованных локальных изображений сохраняются отдельными копиями по хешу содержимого.

Перед первым обновлением существующей базы автоматически создаётся резервная копия SQLite через backup API, включая WAL: `<DB_PATH>.before-dated-v1.bak`. Например, при `DB_PATH=/app/data/debts.db` это `/app/data/debts.db.before-dated-v1.bak`. Установку следует выполнять с сохранением постоянного тома `/app/data` и каталога исходников/версий изображений, как в текущем развёртывании. Код автоматически проверяет копию перед миграцией; при ошибке старт прекращается.

Миграция повторяемая: опубликованные снимки с явными ISO-датами в подписях разделяются по датам, старый проверенный текст импортируется по своей сохранённой дате. Исходные записи остаются в прежнем архиве. Даты недатированных ручных публикаций не угадываются. История до миграции может не содержать сведений о том, какому конкретному фотолисту соответствует сводный распознанный текст.

Повторное подтверждение защищено уникальным номером операции. Если выбранный лист изменился после предпросмотра, весь набор отклоняется без частичной публикации; нужно проверить свежую версию.

После обновления пользователем на BotHost необходимо отдельно проверить Telegram-интерфейс. Локальные проверки с временной базой и имитацией Telegram не доказывают установку или реальную доставку.

Раздел об авторе отложен по просьбе пользователя и в эту версию не входит.
