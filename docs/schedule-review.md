# Черновики и публикация замен

После синхронизации Google Диска бот готовит черновики по группам и датам. При настроенном Gemini используется он; иначе работает существующий OCR через Tesseract. Непроверенный текст студентам не публикуется.

## Очередь администратора

- Открой «Черновики замен» в админке или отчёте синхронизации.
- Один экран показывает один черновик и количество оставшихся. После «Опубликовать» или «Пропустить» этот же экран показывает следующий; после последнего — «Все черновики обработаны».
- Исходные листы открываются отдельными кнопками. Для них переиспользуется одно сообщение с фотографией; при переходе к следующему черновику оно обновляется.
- «Исправить текст» принимает полный исправленный текст до 2800 символов. После ввода черновик снова показывается для проверки. «Отменить правку» возвращает к очереди.
- Решения и ID экранов сохраняются в SQLite. Старые сообщения, накопленные предыдущими версиями, это обновление не удаляет.

## Что видят студенты

После публикации проверенный текст доступен группе. Если для выбранной учебной даты текста ещё нет, бот может показать ближайшие будущие опубликованные замены с явной датой. Уведомление о публикации содержит ссылку именно на опубликованную дату, а не только на автоматически выбранный день.

Общие листы доступны отдельно. Текст замен не является полным основным расписанием; отсутствие строки не означает отсутствие занятий. Консультации остаются исходными фотографиями.

## Уведомления

- После публикации текста уведомляются подтверждённые студенты соответствующей группы.
- После ручной или фоновой синхронизации новых листов уведомляются все подтверждённые студенты. Публикация проверенного текста — отдельное событие.
- Неизменившиеся листы и повторное нажатие «Опубликовать» повторной рассылки не создают.
- Задания доставки хранятся в `schedule_deliveries`. Успешная доставка отмечается в базе; ошибки повторяются при следующей успешной синхронизации. Уведомления о заменённых публикациях не отправляются.
- Telegram не предоставляет здесь транзакцию вместе с SQLite: при аварии между отправкой и сохранением результата возможен повтор отдельного уведомления. Звук и пуш зависят от настроек получателя.

## Хранение

Таблица `schedule_reviews` хранит тексты и статусы `draft`, `published`, `skipped`, `superseded`. Обновление исходных листов создаёт новый черновик; старые кнопки теряют силу, непроверенная версия не становится публичной. Неизменившиеся листы используют сохранённый результат, ручные правки сохраняются.

Учебная дата переключается после 17:00 по будням, после 14:00 по субботам, с пропуском воскресенья. Сохранённый черновик переживает перезапуск; незавершённый ввод правки нужно начать заново.

## Проверки

Проверки используют временную базу и подмену Telegram API. Реальных рассылок и polling при тестах нет.

```bash
python -m unittest tests.test_schedule_review tests.test_schedule_queue_delivery tests.test_gemini_schedule tests.test_admin_ocr tests.test_ocr_runtime tests.test_schedule_history tests.test_gdrive_sync -q
```

Проверяются одна очередь вместо пачки, повторные и одновременные открытия, публикация и пропуск, права доступа, изоляция групп, правильная дата, повторная доставка после сбоя, отсутствие повторной отправки успешным получателям и устаревшие публикации.
