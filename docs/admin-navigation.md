# Админка: навигация и возможности

Состояние инструкции сверено 24 октября 2026 года с опубликованным кодом `7017da8`. Публикация кода в GitHub подтверждена; установка этой версии на BotHost в рамках обновления документации не проверялась.

## Главное меню

Открыть командой `/admin` в личном чате администратора или кнопкой админ-панели в главном меню.

```text
Админка

Требуют внимания:
Заявки студентов: 0
Материалы на проверке: 0
Открытые обращения: 0

[ 👥 Студенты ]       [ 📅 Расписание ]
[ 📢 Уведомления ]    [ 📚 Материалы ]
[ 💬 Обращения ]
[ 🛠 Проверки ]       [ 📊 Статистика ]
[ Обновить ]          [ Главное меню ]
```

Числа — пример. Фактические счётчики берутся из базы. Шесть основных разделов и статистика доступны и при пустых очередях.

| Раздел | Доступные действия |
| --- | --- |
| Студенты | Заявки на вход; подтверждённые студенты по группам |
| Расписание | Google Диск; ручной запрос черновиков и остановка распознавания; очередь; расписание по группам; публикация выбранным группам или всем |
| Уведомления | Уведомление выбранной группе; обычное или важное объявление всем |
| Материалы | Очередь проверки; база знаний |
| Обращения | Отчёты об ошибках и существующая переписка |
| Проверки | Просмотр групп; проверка распознавания |
| Статистика | Активные студенты и открытия разделов за 7 или 30 дней; разбивка по группам |

## Навигация

Вложенные административные экраны получили возвраты в свой раздел и админку. Существующие кнопки карточек, пагинации и действий сохранены. История, редактирование и очистка расписания доступны после выбора группы. Раздел «Проверки» сохраняет оба инструмента проверки.

Переход в административный раздел отменяет незавершённый ввод. Права администратора и личный чат дополнительно проверяются общим обработчиком административных нажатий. Неизвестные административные кнопки предлагают заново открыть `/admin`.

Очистка расписания и удаление старой версии теперь требуют отдельного подтверждения с указанием группы (и номера старой версии). Подтверждение одноразовое; отмена, новый сценарий или изменение выбранного расписания делают его недействительным. Существующие подтверждения удаления материалов сохранены. Реальные удаления и рассылки при разработке не выполнялись.

## Уведомления выбранной группе

В разделе уведомлений можно выбрать группу с подтверждёнными студентами, ввести текст и проверить предпросмотр с числом получателей. Отправка ограничена выбранной группой; подтверждение одноразовое, ошибки отдельных получателей не останавливают остальных.

Проверка перед публикацией: 139 тестов, 131 прошёл, 4 failures и 4 errors. Сравнение с актуальной версией GitHub записано в журнал обновления Obsidian. Новые проверки находятся в `tests/test_group_notifications.py`. Реальные сообщения при проверках не отправлялись.


## Публикация расписания выбранным группам

В разделе «Расписание» нажмите «Опубликовать расписание» и загрузите текст, фото или альбом.
На экране предпросмотра отметьте нужные группы. «Все группы» включается только отдельным нажатием.
Перед публикацией видны текст, число фотографий и количество одобренных получателей без администратора.
Если получателей нет, публикация недоступна. Фото дополнительно показываются администратору до подтверждения.

Кнопка «Опубликовать» сохраняет расписание только выбранным группам и отправляет им уведомления.
«Все группы» сохраняет общую публикацию ALL. Старые версии и альбомы сохраняются существующим механизмом истории.
Отмена и выход в админку отменяют черновик; старые кнопки и повторное подтверждение не запускают рассылку.
Если содержимое для группы уже опубликовано, повторная отправка этой группе не выполняется.
Группы отмечаются администратором вручную: содержимое фотографий автоматически не определяет получателей.

## Ручной запрос черновиков Gemini

В разделе «Расписание» доступна кнопка «Запросить черновики». Она использует уже скачанные актуальные листы замен; для загрузки новых листов сначала нажмите «Обновить с Google Диска».
Кнопка доступна также после ошибки подготовки черновиков. Пока обработка идёт, повторное нажатие не ставит ещё один запрос в очередь.

При временной ошибке соединения или HTTP 500/502/503/504 выполняются до четырёх попыток с паузами 2, 4 и 8 секунд.
Ограничение ожидания распознавания снято. Проверка доступа без фото сохраняет сетевое ожидание 20 секунд. Кнопка «Остановить распознавание» завершает отдельный процесс запроса и освобождает возможность нового запуска. Ошибки ключа, доступа, квоты и сертификата не повторяются автоматически; проверка TLS остаётся включённой.
Если все попытки неудачны, бот показывает причину и позволяет запросить черновики позже. Успешное распознавание тех же фото берётся из существующего кэша: опубликованные, пропущенные и вручную исправленные результаты не перезаписываются.
Публикация студентам остаётся отдельным действием администратора после проверки черновика.

Синхронизация Google Диска скачивает листы и доставляет уведомления о новых файлах, но не вызывает Gemini. Распознавание запускается только по явному действию администратора. Если администратор ушёл с экрана во время запроса, результат не возвращает его в очередь автоматически: подготовленные черновики можно открыть кнопкой «Черновики замен».

## Уборка экранов

Уведомления, открытые методички, общие листы и связанные фото/альбомы учитываются общей уборкой. Новое содержимое сначала отправляется, затем убираются старый экран и его фотографии. Фото предпросмотра сохраняются при выборе получателей и убираются при завершении или отмене. История расписаний, материалы в базе, необработанные заявки и правила прочтения важных объявлений сохраняются.

Прежние номера очереди Gemini и исходного фото подхватываются из сохранённых настроек. Сообщения, номера которых раньше нигде не сохранялись, нельзя автоматически найти в истории Telegram; исходная карточка с кнопкой убирается при нажатии на неё. Удаление выполняется с учётом ограничений Telegram.

## Распознавание по страницам

Новые многостраничные листы распознаются по одной фотографии. Структурированные результаты страниц сохраняются в отдельном кэше SQLite, поэтому повторный запрос после сбоя не начинает успешные страницы заново. Готовый черновик создаётся только после обработки всех известных страниц и завершения объединения; неполные результаты не показываются как готовое расписание.

Сохраняются порядок частей, номера объединённых уроков и отдельные строки подгрупп. Строки с непересекающимися номерами объединяются в порядке страниц. При пересечении номеров выполняется запрос всех страниц для конкретной группы; при неоднозначном продолжении или порядке частей — запрос документа целиком. По совпадению текста строки не удаляются. Если контекстный запрос не удаётся, страницы остаются в кэше, а черновик не создаётся.

Известная недоступная страница и разрыв нумерации частей блокируют создание неполного черновика. Существующий кэш готовых документов остаётся совместимым; ручные исправления и публикации тех же листов сохраняются.

Диагностика Gemini содержит имя настроенной модели, число изображений, размеры фото и запроса, длительность и исход попытки. Ключи, URL запросов, пути к фото, фамилии и текст расписания в неё не записываются. Размер порции уменьшен, но внешние ошибки Google всё ещё возможны, в том числе при запросе полного контекста.

## Статистика использования

Открой «Админка → Статистика». Доступны периоды 7 и 30 дней, обновление и разбивка активных студентов по группам. Показываются открытия расписания, работ, материалов, полезного и профиля. Действия администратора не учитываются; события записываются для подтверждённых пользователей. Активность до появления учёта задним числом не восстанавливается.

Подробная инструкция по обновлённой статистике: [периоды, люди, группы и история действий](usage-people.md).
